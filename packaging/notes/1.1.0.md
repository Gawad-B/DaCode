DaCode 1.1.0: source control, a terminal, blame, structural text objects — and from now on DaCode
updates itself.

This release has to be installed by hand, the way 1.0.0 was. It is the first with the updater, so
every release after it arrives on its own: DaCode checks once a day, downloads and verifies the new
version, and the bell offers **Restart now**.

## What is new

- **Source control, as in VSCode.** `ctrl-shift-g` opens it: the branch and how far it is ahead of
  or behind its upstream, a commit box (`ctrl-enter` commits), and Merge, Staged and Changes groups
  with stage, unstage, open and discard on every row. Clicking a change opens its diff in a tab.
  Click the branch to switch or create one; pull, push, fetch, stash and history are in the `…`
  menu, the new **Git** menu and the palette.
- **A terminal under the code.** `ctrl-t` (or `` ctrl-` ``) opens your shell in the project folder.
  Several tabs, a height you drag, mouse selection with `ctrl-shift-c` to copy, colours, and the
  mouse for full-screen programs like `htop`.
- **Git blame.** Who last changed the caret's line, after the line; `alt-b` shows a column of it.
  A commit or checkout made outside DaCode shows up at once.
- **Structural text objects.** `af`/`if` a function, `at`/`it` a type, `aa`/`ia` an argument,
  `ac`/`ic` a comment — `daf`, `cia`, `2af` for the one around it. Without Vim keys: `alt-f`,
  `alt-t`, `alt-a`, and `shift-alt-→` / `shift-alt-←` to grow and shrink a selection by syntax.
- **Indentation from the syntax tree** for Rust, Python, JavaScript/TypeScript, C/C++, HTML and CSS.
- **Rebind keys in Settings.** On the Keys page, click a command and press the new key. A key that
  is taken says by what; every menu and the palette show the key you chose. It is saved to
  `init.lua` as `dacode.keys { … }`.
- **DaCode updates itself** — set **Updates** to automatic, notify or off on the Files page. A
  `.deb` or `.rpm` install is never changed behind its package manager: the bell gives the command.

## Keys that moved

- `ctrl-w` closes the file. Split and window commands moved under `ctrl-k` (`ctrl-k v`, `ctrl-k s`,
  `ctrl-k h/j/k/l`).
- `ctrl-t` toggles the terminal; go to a symbol in the project moved to `ctrl-shift-t`.
- The **Run** menu became **Git**; running the project is under **Terminal** and on the ▶ button,
  which now runs it in the terminal.

## Fixed

- Key bindings written with `dacode.map` in `init.lua` never fired with Vim keys off. They do now.
